## 从 V3.1 首轮失败到资格验证

原始 Rule/V1/V2/V3 通过 manifest 封存，原始无效 fixture 和语义失败保留。V3.1 引入独立 Runtime：类型化持久状态、P0/P1 固定上下文、回执预算核对、假设状态机、柔性收敛、有界 JSON/schema 修复、重复失败熔断及 Provider 诊断。

历史预算为 28 次探索调用，另分 8 次补证、12 次纠错、3 次提交、12 次总 schema 修复、10 次 Provider 重试；单结构化输出最多两次修复，单 Provider 请求最多两次重试，总轮次 20，Token 上限 300,000，输出上限 2,500。这是多项 Runtime 干预，不是单一压缩消融。

初始测试门禁 81 passed，其中 32 项新可靠性测试。V3.1 八场首轮仅工作流 1/8、根因 1/8、服务 1/8；七场受预算/上下文/480 秒时限终止，累计 1,122,208 Token。唯一完成的代码异常候选通过合同和 HTTP 重放。不能把条件正确率 1/1 宣传为八场景 100%。

| 后续 Runtime | 完成情况 | 发现 |
| --- | --- | --- |
| 3.1.1 | 已派发 2 场中完成 1 场，原计划 5 场 | N+1 输出及两次修复截断，后因遥测问题停派 |
| 3.1.2 | 0/5 | 紧凑 schema 避免截断，却暴露提交预算与字段描述回归 |
| 3.1.3 | 4/5 | N+1 字段仍超长 |
| 3.1.4 | 5/5 | schema 定向字段修复；测试门禁 117 passed |

这些是协议资格验证，不加入 RCA 准确率，失败也不覆盖首轮 1/8。字段修复只替换精确超长路径，保留其他引用、类别和服务，不直接截断字符串。单独真实模型修复探测对五个保留失败输出使用 3,120 Token，验证协议修复而非因果正确。

## 序列化与可观测容量

后续实现按一次遍历快照读取脱敏配置。成对测量输出一致，序列化中位数由 8.78 秒到 25 毫秒、配置读取 3,425 次到一次，不能外推为整个工作流提速。

Jaeger 曾占 Docker VM 6.135 GiB，查询超过适配器 8 秒超时。后续限制 10,000 Trace、Go 软内存 640 MiB、容器 768 MiB；清除了易失 Jaeger 历史，但保留 PostgreSQL 与冻结工件。28 次后续只读观测无查询失败，最大延迟 0.662 秒，末次内存 584.8 MiB，仅是有限窗口。

最终冻结 V4.1 完成 8/8、根因/服务 7/8，1,461,870 Token、平均 78.75 秒，当时测试门禁 189。原记录只举出一场 Critic 遗漏，后续独立审计确认八场均有遗漏；当前引用保护尚未重跑完整 Benchmark，见 [审计导读](independent-final-audit-zh.md)。
