# Phase 4 对抗审计：中文导读

[文档导航](index.md) · [英文原始记录](phase4-adversarial-audit.md)

历史审计试图证伪能力、来源与恢复声明，不是渗透测试认证。原记录保留 36 项静态完整性检查、实际跨源请求 403/非法 Host 400/旧版本派发 409/通用部署 409，以及 189 项当时测试门禁。

调查数据库角色不能读取评测、Checkpoint 和 Provider 账本；12 张表及日志中的实际 key 扫描无匹配。Runtime/AST 测试拒绝穿越、密钥、任意 shell/HTTP/SQL、超大参数、提权、import、属性、循环和保护路径。四次真实模型攻击输入探测是标注 fixture，不是生产事故或 RCA 成功。

首次 crash 状态恢复后语义失败，放开 `services/app.py` 的尝试被两个既有测试拒绝，最终改为抽取纯业务 checkout。公开响应、工具回执与补丁反馈增加了恢复身份约束，不代表所有物理工作 exactly-once。

六条旧测试候选误带 `AI_GENERATED`，原标签保留并从真实模型分数排除；新测试记录使用 `TEST_FIXTURE`。首次标签迁移 SQL 门禁为 40 failed / 147 passed，修复后 187 passed，回执身份检查后 189 passed，失败没有被抹除。

冻结版本仍有 Critic 引用交接遗漏、可读 fault helper、重试风暴误判和旧候选次数统计缺口。后续独立审计将遗漏范围从一例纠正为八场，当前保护修复另记，不能更改冻结分数。

Live API 仅回环、没有完整多租户 RBAC；单进程 run 所有权不是分布式租约。候选共享内核和依赖，强制终止可能遗留临时命名空间。哈希/只读文件不是 WORM，密钥扫描和四次注入也不证明所有泄露渠道安全。
