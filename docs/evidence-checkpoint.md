## 证据与上下文

原始工具结果先持久化，再按模型上下文预算构造视图。日志按实际返回样本聚类，指标保留测量窗口，Trace 保留重要 span、服务边与重复调用，代码使用真实行号和源码范围。摘要不是原始数据的替代品，必要时可用 detail 工具回读。

重要性由直接性、异常标记、疑似服务相关性、来源唯一性、跨来源服务重合和新近性组成。这些都是显式选择启发式，不是概率、因果分类器或统计独立性证明。来源族去重避免把同一 Trace 的摘要和详情误计为两个独立来源。

编译器以完整对象选择和遗漏计数控制预算，不切断 SQL、原子字符串或 JSON。普通观测可以因空间不足被省略，根因必需引用先于可选排名保留；无法容纳时明确报错。模型不能引用仅存在数据库、但没有交付到当前输入中的证据。

## 测量口径

| 数据 | 含义 |
| --- | --- |
| 原始/编译后字符数 | 表示指定构造阶段的体积，不是完整请求的真实 Token |
| `字符数 / 4` | 明确标记的估算；不代替 Provider 用量 |
| Provider input/output/total | 服务端实际报告用量，缺失或中断时允许未知 |
| pinned 状态大小 | 独立记录 P0/P1 关键控制状态的开销 |
| 完整消息信封 | 包含角色、工具 schema、对话和嵌套 JSON，需按真实序列化检查 |

压缩比降低不能单独证明效果更好。历史 V3 虽用量较少，但工作流只完成 2/8；提前失败也会降低累计用量。

## 恢复边界

| 持久化对象 | 能恢复什么 | 不能承诺什么 |
| --- | --- | --- |
| Checkpoint | 同一 run 的阶段、假设、错误、读取与待执行动作 | 不自动保证所有外部物理动作只执行一次 |
| 工具回执 | 已完成调用及其预算核对 | 调用完成但回执未提交时仍可能重做 |
| 公开模型响应日志 | 已提交响应、用量与诊断可重放；请求摘要不匹配时拒绝 | 远端响应未落盘前丢失可能重复请求与计费 |
| 候选验证工件 | 复用已提交测试结果及失败反馈 | 沙箱完成但结果未提交可能重复验证 |

Provider 不持久化 `reasoning_content` 等隐藏推理字段。系统没有分布式执行租约、全局 exactly-once 事务或端到端计费保证。

## 历史恢复实验

首次真实 SIGKILL/exit 137 后恢复了相同状态，但随后语义提交失败，消耗 191,054 Token，不能计为端到端恢复成功。后续修订完成同一 run 恢复，保留一次 resume、12 次真实调用和 136,881 Token；Critic 仍为 `PARTIALLY_VERIFIED`，候选未部署。两次记录独立保存，不加入八场景准确率。

本机 HTTP 429/500、无效 JSON、超时和合同测试 fixture 只验证协议与持久化，不算云端模型诊断。详情见 [恢复与安全历史导读](phase4-recovery-security-zh.md)。
