# 第二阶段对抗审计：中文导读

[文档导航](index.md) · [英文原始记录](hostile-audit.md) · [原始机器报告](phase2-audit.json)

历史扫描检查隐藏文件，但排除 `.git`、`.env` 和字节码，不打印凭据值。`mock`、`sample` 等命中分别来自样本字段、种子、测试和说明，不能仅凭关键词判断伪造。规则答案明确标识，故障注册表是评测元数据；本机超时/429/500 fixture 不算真实模型成功。

Investigator 工具拒绝注册表、评分器、报告、配置、`.env`、任意 SQL、Redis key 枚举及 shell；当时 `services/app.py` 因混合故障逻辑而不可读。评分器只在终态后加载真值，结果不写回调查历史。能力隔离不是独立操作系统边界，模型仍可能从合法观测推断机制。

保留的修复包括：接受 diff 缺末尾换行但维持路径/hunk 校验；排除诊断 SQL 自污染；查询计数改用 `(userid, dbid, queryid)`，新/重置计数保持未知；长历史分页与预算；Critic 结构契约；标识迁移引发的计划失效与 Windows 编码重复 runner 行。

当时仍仅支持 pricing，缺完整沙箱、鉴权、HA、通用发布与精确恢复。它们是第二阶段边界，不能误写为当前只有一个候选 profile；后续四类函数和恢复见 [当前工程文档](agent-runtime.md)。旧失败、无效 fixture 和污染结果保持原样，不重新评分。
