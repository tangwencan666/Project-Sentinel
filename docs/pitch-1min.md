# 1 分钟项目介绍

**问题：**“微服务出故障时，看到报错不等于找到根因。工程师需要把日志、指标、调用链、数据库状态和代码联系起来。”

**解决：**“Sentinel 让 AI 按步骤调用工具调查，保存每条证据和引用，再提出根因与修复候选。候选先在沙箱测试，由人审查。”

**技术：**“我用 Python/FastAPI 搭了六个电商服务，接入 PostgreSQL、Redis、Kafka 兼容的 Redpanda 和 OpenTelemetry；Agent 使用 deepseek-chat 和自建 Runtime。”

**结果：**“最终 V4.1 的八个受控场景全部完成调查，七个根因正确，仍用了约 146 万 tokens。这是小样本实验，不是生产准确率。”

**工程亮点：**“最值得讲的是 V3 压缩上下文后工作流跌到 2/8。我保留了失败，追查状态、工具反馈和恢复协议，再改进 Runtime。现在展示真实回放，不需要现场调用模型。”
