# 24 个尖锐问题与诚实回答

## 1. 这不就是 DeepSeek 套壳吗？

模型是推理组件。这里还实现了真实目标系统、故障注入、受限工具、证据账本、预算、恢复和候选验证；可以逐条查到工具输出与测试。但我不会把这些工程工作说成训练了新模型。

## 2. 没有 AI，用规则不是更准吗？

本固定基准中 Rule 根因 7/8，和 V4.1 相同，而且没有模型 token 成本。项目没有证明 AI 全面更好；研究价值是跨证据调查、代码关联和可验证候选，仍需在更开放事故上验证。

## 3. 7/8 (87.5%) 只有八个样本，有统计意义吗？

它只能描述这次实验。一个结果就改变 12.5 个百分点，不足以估计生产准确率，也没有重复样本分布。我会展示分子分母和每场记录，不包装成泛化结论。

## 4. 故障是你设计的，模型是不是已经知道答案？

显式真值、评分器和场景注册表不在调查工具权限里，但可读 fault helper 暴露实验线索，规则基线也编码了领域知识。因此不能称为完全盲测，独立设计的未见故障仍是未来工作。

## 5. 为什么不用 LangGraph？

为了直接检查每次预算、状态与引用转换，我实现了小型 Python Runtime。代价是要自己维护恢复协议；框架迁移不是能力证明，也不是本轮要扩大的范围。

## 6. 为什么不用现成 AIOps 产品？

这是检验工程能力的作品集，不是声称替代商业产品。我没有做采购比较；现有生产产品的接入生态和运维成熟度并未在这里复现。

## 7. 146 万 tokens 查八个故障是不是太贵？

是当前明显限制，且没有价格配置时不能编造人民币成本。输入占主要部分；优化必须同时保持完成率和证据覆盖，不能重演 V3 的提前失败“省 token”。

## 8. 为什么 Critic 全是 PARTIALLY_VERIFIED？

证据与有限测试没有排除所有替代原因，某些事故也没有代码候选。保守标签比虚假的 VERIFIED 合理，但引用交接确实有缺陷，不能把全是部分验证当作验证器成功的证明。

## 9. 你敢放生产吗？

只读录制 Demo 可以按部署边界准备公开展示；Live 调查系统尚不具备生产多租户鉴权、执行租约和发布治理。不能把两者混为一谈。

## 10. AI 修错代码怎么办？

限制可改函数、diff 与 AST，执行固定合同和真实依赖重放，再要求人工审查。当前通用候选不自动发布；测试通过并不能消除业务、并发和财务风险。

## 11. 九项测试是不是针对答案写的？

合同测试是固定验证边界，不由当前模型候选改写；基线失败与候选通过均保留。但覆盖范围仍有限，八个重放输入不能代表所有业务输入。

## 12. Replay 是不是你编的动画？

事件 ID、时间顺序、工具结果与 run_id 来自冻结记录。播放器只改变游标。精确 Fault Trigger 时间未保存，所以界面显示首次观察时间，没有补造事件。

## 13. 为什么不现在现场调用模型？

录制能在五分钟内稳定展示完整证据链且不花费模型 token；顶部明确标识。真实 Live 调查保留为本地显式选项，不能让回放冒充新调查。

## 14. V3 更省 token，是不是其实优化成功了？

不是。工作流只完成 2/8，根因 1/8，较少 token 受到提前终止影响；没有完成任务的成本不能直接与成功调查比较。

## 15. V4.1 的提升全部来自 Context Engineering 吗？

不能这样归因。Runtime、恢复协议、可读业务源码及实验环境都变化了，这是独立 benchmark-v2 发布队列，不是单变量消融。

## 16. 你有没有挑最漂亮的一次？

Demo 挑了适合讲解的成功案例，但正式表保留各版本的首次记录，包括 V3/V3.1 失败和 V4 混杂项。一个好看的 Demo 不代表全部八场都能修复。

## 17. 重试风暴为什么到最后还错？

模型把 payment 快速 503 视为根因，而没有正确定位 order 的五次立即重试放大；还推测未读取的故障键。没有为该场景补特殊规则或重新刷分。

## 18. 你能保证没有 Prompt Injection 吗？

不能保证模型永远不被文本误导。实际边界是工具与路径权限、参数校验和受限补丁执行；已有攻击样本通过不代表覆盖所有攻击。

## 19. Checkpoint 能保证不重复扣费吗？

只能复用已经持久化的响应和工具回执。若远端已计费、本地提交前崩溃，仍可能重发；没有端到端 exactly-once 计费保证。

## 20. Sandbox 是真正隔离的沙箱吗？

它是受限进程与专用数据库 schema、缓存 namespace、Kafka topic 的验证环境，仍共享容器/内核。不能用于任意恶意仓库，也不能等同独立虚拟机隔离。

## 21. 267 个后端测试就是 267 次真实事故吗？

不是。这是回归测试用例数量，包含协议 fixture 和边界测试。真实八场景 benchmark、17 项前端单测和浏览器检查分别报告，不混加为事故样本。

## 22. 没网时能不能打开？

准备好 Docker 镜像后，录制服务只读本地资源，不依赖模型或外部 API。首次构建和下载依赖通常需要网络；源码 ZIP 本身不包含 Docker 镜像，不能声称首次离线安装也一键完成。

## 23. Hash 能证明数据不是伪造的吗？

Hash 只能证明相对清单的内容未变，不能防止同时改数据和清单。可检查源记录、失败历史、事件关联和归档；没有外部签名审计就不声称独立认证。

## 24. 下一步最重要的是什么？

先补 Critic 引用完整性与独立验证，再扩展独立事故和多模型测量、成本与审批边界。这些列入 Future Work，本轮不实现，也不承诺尚未测出的收益。
