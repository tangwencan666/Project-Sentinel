## 编译表示

日志按服务、级别、路径、状态和归一化消息聚类，保留实际样本次数、首末时间与代表样本。指标包含测量窗口、基线/当前/峰值/变化/趋势；无效或非有限基线为未知，事前窗口不必然健康。

Trace 保留最长嵌套 span 链近似、慢/错误 span、服务边及重复客户端调用；SQL fanout 只统计带 `db.statement` 的 client span。重叠时长不可相加。代码预览保留完整行、实际范围、符号和局部调用关系。

选择启发式综合直接性、异常、疑似服务、来源唯一性、跨源重合和时间。先覆盖可容纳的不同来源族，再允许重复；完整对象超预算时记录遗漏和原始读取引用，不切断原子字符串、SQL 或 JSON。重要性不是概率或因果证明。

P0 保留未解决错误，P1 保留关键证据；调查包避免重复 P1。详情工具绕过编译器，提供完整 span 页、JSON 路径/对象偏移或源码行；读取登记只计实际交付范围。

## 观测与用量

基础设施探测使用真实只读 SQL、Redis INFO/TTL/PING、Kafka offset。计数器变化需测量起止和 elapsed；重置或缺失值为未知。Redis 全局计数包含 Sentinel 控制流量，不等于目录缓存命中率。数据库查询观测与业务连接池计数分别获取。

每包记录原始/编译字符数、比例、保留/遗漏 ID 与原因、来源族及固定状态大小；成功响应后附实际 Provider input Token 与调用 ID。字符/4 只是估算，不代替实际用量。

## 资格与首轮约束

V4 当时门禁 138 passed，另有七项真实依赖只读断言。压缩 profile 只测表示体积，不测准确率。每个场景只在操作员校验注入有效后派发一次，标签和校验证据不交给 Investigator；评分器终态后才接真值，失败答案不重跑覆盖。

保留 3.1.4 的数值预算、2,500 输出 Token、300,000 工作流 Token和单输出两次修复。继承 Runtime 修复及 Jaeger 容量变化，因此不是纯压缩消融。V4 首轮完成 7/8、根因 5/8，两场受无关 consumer 故障混杂，原分保留并排除 Pareto。

后续独立发布 V4.1 使用 benchmark-v2，不能回写 V4 首轮。完整结果见 [评测导读](phase4-evaluation-zh.md)。
